2 Controllability: three definitions

The definitions are stated for the linear time varying case, which costs nothing extra and covers the time invariant one.

(a) Zero state controllability

Given a pair , there exists a final time and an input on such that the state is driven to the origin.

If this holds for every pair the system is called completely zero state controllable.

(b) Controllable from the origin

Given a target state and a start time , there is a final time and an input that reaches it starting from rest.

If this holds for every and every the system is called completely controllable from the origin.

This property is also called reachability in much of the literature.

(c) Controllable

This is (a) and (b) together with complete controllability.

Any starting point can be steered to any target in finite time.

The three definitions differ only in which endpoint is pinned to the origin.

Question 1: for a continuous time LTI system, are (a) and (b) actually different?

No, for a continuous time LTI system the two coincide, and both reduce to the rank test on .

The reason is that is always invertible, so a trajectory can be run backwards without loss.

Steering to zero requires the integral to supply , which is an arbitrary vector as ranges over the space.

In discrete time the two genuinely differ, because can be singular there and some directions collapse on their own.

Question 2: the definitions ask for the existence of some finite . Why is no bound placed on how large it may be?

For an LTI system the choice of horizon turns out not to matter at all.

The remark in Section 5 makes this sharp: any point of the controllable subspace can be reached in arbitrarily small time.

What does change with the horizon is the energy needed, and a short horizon demands a very large input.

Controllability is a yes or no structural question, and the cost of exercising it is a separate matter taken up in Demo D2.

For a time varying system the horizon can matter, since may be zero over some stretch of time.

Question 3: nothing in the definitions constrains the size of . Is that realistic?

It is not, and it is a deliberate simplification.

Real actuators saturate, so the reachable set of a bounded input problem is much smaller than the controllable subspace.

The unbounded definition is still the right first question, because a system that fails it cannot be fixed by a bigger actuator.

Once controllability holds, the practical questions become how much effort is required and whether the actuator can supply it, which is the subject of Demo D10.

A note on the rank of a matrix

Given , the rank of is either of two equivalent things.

(a) The maximum number of linearly independent column vectors.

(b) The maximum number of linearly independent row vectors.

That these two numbers always agree is a standard result of linear algebra, and it is the reason the rank test can be read either way.

In practice: rank is a discontinuous function of the entries, so a matrix that is numerically close to rank deficient still reports full rank. The honest measure is the smallest singular value, and every demo on this page reports it alongside the rank.

Choosing to put the closed loop poles at desired locations is called pole placement.

When is not completely controllable, feedback can still move the poles of the controllable modes, but the uncontrollable modes keep their eigenvalues whatever is.

Question 1: the gains enter linearly for a single input system. Why does that matter, and does it survive for several inputs?

Linearity means that matching coefficients gives a square linear system in the gains, so it has a unique solution whenever the coefficient matrix is invertible.

That coefficient matrix turns out to be built from , which is why controllability is exactly the invertibility condition.

For several inputs it does not survive: the gain matrix has entries but the polynomial still has only coefficients, and products of gains appear, so the map is neither square nor linear.

This is also why the two standard pole placement functions behave differently: acker and place in MATLAB's Control System Toolbox, and control.acker and control.place in the Python Control Systems Library.

The acker functions use Ackermann's formula of Section 12 and accept only single input systems, while the place functions also accept several inputs and use the extra freedom to shape the eigenvectors as well as the eigenvalues.

Question 2: pole placement can achieve any polynomial. Does that mean any closed loop behaviour is achievable?

No, and this is a common misreading.

The poles fix the modes of the closed loop, but the size of the input and the transient overshoot are not free.

Zeros of the plant are also untouched by state feedback, so a right half plane zero keeps limiting the achievable bandwidth.

Placing poles very far left simply moves the difficulty into the actuator, which is the subject of Section 13.

13 How to choose the gain or the desired polynomial

Pole placement answers where the poles can go, and says nothing about where they should go.

The choice is a trade off between speed and the size of the gains.

  • Eigenvalues further to the left make the system converge faster.
  • But that implies larger gains, and larger gains have costs.
    • They may lead to actuator saturation.
    • They may amplify the effects of noise.
    • For certain systems, they may destabilize the closed loop.
The last point deserves emphasis. A gain computed from a model is applied to the real plant, and the real plant has unmodelled dynamics. A very aggressive design has small stability margins, so a small modelling error can push the true closed loop unstable even though the design looks perfect on paper.

Question 1: why does a larger gain amplify measurement noise, given that the noise is not in the model at all?

The controller does not see but a noisy measurement of it.

The term is noise injected straight into the actuator, scaled by the gain.

Doubling the gain doubles the noise in the control signal while only modestly improving the response.

Choosing the gain by trading the two effects against each other is what the linear quadratic regulator does automatically, and it is where this course goes next.

Question 2: give a concrete mechanism by which a larger gain destabilizes a real system.

A time delay is the clearest example, since every real actuator and sensor has one.

A delay contributes a phase lag that grows with frequency.

A higher gain pushes the closed loop bandwidth up, so the loop operates where the lag is larger, and the phase margin is eaten away.

A flexible structural mode above the design bandwidth does the same, since a fast controller starts to excite it.

Question 3: suggest a reasonable starting point for the desired poles of an unfamiliar plant.

A common first choice is to keep the open loop pole pattern and simply reflect any unstable poles across the imaginary axis.

That is the cheapest possible stabilizing design, since it changes the polynomial as little as possible.

A second choice is the Butterworth pattern, which places the poles evenly on a circle of a chosen radius.

Then increase the radius until either the actuator saturates or the noise in the control signal becomes unacceptable, and stop just before that.

Raising moves both eigenvalues further from the origin, which speeds up the response, and lowering turns them towards the imaginary axis, which makes the response ring. The pole map below the time plots shows the two eigenvalues for the current slider values.

Question 1: raise the pole radius until the control signal clips. What happens to the actual response, and why is it worse than a slower design?

Once the input clips, the closed loop is no longer the linear system that was designed.

During saturation the loop is effectively open, so the plant runs on its own dynamics, and here those dynamics are unstable.

The response then departs from the ideal linear design, and a radius that is too large settles more slowly than a moderate one, or does not settle at all within the time window when the limit is tight.

The bottom right plot shows this, since the settling time curve reaches its minimum at a radius past the point where the effort curve crosses the limit line, and rises again beyond it.

The practical rule is to choose the fastest design whose peak effort still fits inside the actuator with margin.

Question 2: switch the actuator limit off and raise the noise instead. What breaks first?

The control signal becomes visibly rough long before the state response does.

The noise enters the input multiplied by the gain, so its amplitude in the control signal is roughly times the sensor noise level.

The state is much cleaner because the plant integrates the input and so acts as a low pass filter.

An actuator asked to chatter at that amplitude wears out, draws power and can excite unmodelled flexible modes.

The gain curve in the bottom right plot is therefore a direct proxy for how noisy the actuator command will be.

Question 3: lower the damping ratio towards 0.2 at a fixed radius. What is the cost of that choice?

The poles move closer to the imaginary axis while keeping the same distance from the origin.

The response rings for several cycles before settling, so the settling time gets worse even though the poles are just as far from the origin.

The peak control effort also rises, because the controller keeps reversing the input to sustain the oscillation.

A damping ratio near is the usual compromise, which is why the Butterworth pattern sits there.

14 Summary of the module

The coordinate freedom

A similarity transformation relabels the state without changing the system.

Eigenvalues, the transfer function and controllability are all invariant under it, which lets us pick whichever coordinates make the question easiest.

All four answer the same yes or no question, and they differ only in what they need as input and in how well they behave numerically.

When the test fails

The controllable subspace names what can still be reached, and the Kalman form splits the system into a controllable block and an untouchable one.

Stabilizability, meaning that is already stable, is the condition a design really needs.

Full state feedback

Controllability is exactly the condition under which the closed loop characteristic polynomial can be made anything we want.

Computing the gain

By hand, expand and match coefficients with the desired polynomial. In one step, use Ackermann's formula for a single input system.

Ackermann's formula is exact but numerically delicate, since it inverts and evaluates a matrix polynomial.

Three traps to remember
  • Full rank on paper is not the same as controllable in practice, and the smallest singular value is the honest measure.
  • Repeated eigenvalues with a single input always leave one combination uncontrollable, no matter how is chosen.
  • Poles placed far to the left buy speed with gain, and gain is paid for in saturation, noise and lost robustness.

The first is about numerics, the second about structure and the third about the actuator.

Final question: you are handed an unfamiliar model and asked to design a regulator. What is a sensible order of attack?

Start by computing the open loop eigenvalues, since they tell you what is wrong and how urgent it is.

Check controllability with the Hautus test at those eigenvalues, which also names any mode that fails.

If a mode fails, ask only whether it is stable, because that decides between an inconvenience and an impossible problem.

Report the smallest singular value of the Hautus matrix alongside the yes or no answer, since a nearly uncontrollable mode will need gains no actuator can deliver.

Choose a first pole pattern by reflecting unstable poles and keeping the rest, then increase the speed gradually.

At each step simulate with the real actuator limit and the real sensor noise, and stop at the last design that still behaves.

Finally check the design against a perturbed model, because the gain was computed from a model and will be applied to a plant.
